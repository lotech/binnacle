# Changes made to the unit outside the app

Binnacle itself installs as a normal app. Getting the most out of the unit took a few changes to the stock system as well. None of them touch the system partitions, and none send anything to the car or the MCU (an MCU write would be listed here with its undo, and only after the owner approved that exact message). Each one can be undone with the command shown.

**No stock apps were removed.** The stock dash (`com.xbs.launcher1`), the CAN app, the camera app and ZLink all stay installed. The only things uninstalled were this project's own test builds and, on the owner's unit, Apple Music (a user app; see below).

## What needs the unit's ADB

Some Binnacle features run a fixed command on the unit through its own ADB (on the unit itself, 127.0.0.1:5555). A fresh unit has ADB off until it is switched on once (see [ADB-GUIDE.md](ADB-GUIDE.md)), and this firmware turns it off again at every restart unless it is kept on. Until then, these don't work:

- **Wireless CarPlay after a restart or a CarPlay update:** Binnacle can't give xcertplay its location permission back, and CarPlay then fails to connect.
- **End CarPlay:** the button opens Android's Wi-Fi screen instead, to turn Wi-Fi off and on by hand.
- **Pausing Wi-Fi scans during CarPlay:** music and calls can stutter away from home.
- **The Wi-Fi icon rejoining home Wi-Fi.**
- **Bluetooth auto-connect** (Display tab): shows "Needs network ADB".
- **Screenshots from the power bar.**

Everything else works without it: the dash, the car data, the camera in the dash, CarPlay drawn in the dash, updates and setup's other steps.

Once ADB is on, setup's **Set up the unit** step (or Apps → Unit) makes the changes below that are marked *Unit setup* with one tap, and each can be undone there. **Other unit software.** These were tested on System version 202302282110 (the stock CarSetUp screen shows it, and so does Binnacle's Unit page). On any other version, setup's one tap makes only the plain Android settings (keep unlocked, pop-ups, GPS dumps, Bluetooth volume fix). Android Bluetooth, the stock camera and CarPlay calls stay as switches on the Unit page, marked as not tested yet. **Units without root.** Every change here except the pop-ups one runs as root (`su 0`), and the ADB firewall does too. Some units have no `su` (issue #90). Binnacle checks for it when it reads the unit's state: without it, setup's one tap leaves those changes out, the Unit page marks them "Needs root" with the switch off, and it warns that ADB stays open to the Wi-Fi until the unit restarts (the unlock isn't kept over a restart without root). If Binnacle can't keep ADB off the Wi-Fi for another reason, the Unit page says so too. Switching ADB on the first time is the one step an app can't do: setup shows how (three lines typed into EngineerMode's Adb shell). Some of these units still give root to ADB itself: on Dash 3 (no `su`, a `userdebug` build with `ro.debuggable=1`), `adb root` from a computer works, so the root rows below can be made by hand by running `adb root` first and then each command without `su 0` (`adb root` lasts until the next restart). [COMPATIBILITY.md](COMPATIBILITY.md#wireless-carplay-on-a-dash-without-su) lists what that took for wireless CarPlay.

**ADB stays off the Wi-Fi.** Android 10's ADB listens on every network once it is on, so each time it starts (and each time the screen comes on) Binnacle drops port 5555 for everything but the unit itself, and on the unit itself lets only Binnacle, root and the shell user connect (firewall rules, as root). A computer on the Wi-Fi can't connect until you turn on Apps → Unit → Network ADB. The rule goes at a restart, so the port is reachable for the few seconds between the unit booting and Binnacle starting.

Commands assume `adb connect <unit-ip>:5555` first. `su 0` gives root on this unit (`su -c` doesn't work).

> **⚠️ Network ADB is root for anyone on the same network.** This firmware's adb asks for no key or password, and `su 0` works from it. While port 5555 is open to the network (before Binnacle starts, or with Apps → Unit → Network ADB on), any device on the same Wi-Fi can take full control of the unit: that includes a shared or public network, and the unit's own hotspot if you share it. Keep it on only on networks you trust, or switch it off when you're done (`adb shell su 0 setprop persist.adb.tcp.port ""`, then reboot). Details: [ADB-GUIDE.md](ADB-GUIDE.md#️-security-warning-read-this-before-making-it-persistent).

> **Removing Binnacle doesn't undo most of these.** Apps → Advanced → Remove Binnacle turns the stock camera screen and the stock dash's pop-ups back on, and stops ADB staying on after a restart, before it uninstalls; the other changes stay until you undo them (Apps → Unit → Unit setup, before removing, or the Undo commands below). If the stock camera screen is still off afterwards, run its Undo command, or the camera won't open by itself in Drive any more.

| Wi-Fi scans paused during CarPlay | Each auto-connect scan takes the single radio off CarPlay's Wi-Fi Direct channel for about a second: music and calls stutter away from home | On by default (owner, 5 Nov); off in Apps → Display → Pause Wi-Fi scans during CarPlay. Tapping the Wi-Fi icon off home Wi-Fi, with CarPlay not running (or just ended from the icon), runs `service call wifi 58 i32 1` and then End CarPlay's `svc wifi disable && sleep 2 && svc wifi enable`, so Android rejoins home Wi-Fi at once (Wi-Fi is usually already on, so enabling it alone did nothing); with CarPlay running and the pause off it runs `service call wifi 58 i32 1 && svc wifi enable`, which keeps CarPlay up; not while CarPlay runs with the pause on | Switch it off; a reboot also resets scanning to on (`adb shell service call wifi 58 i32 1` by hand) |

## Calls and Bluetooth audio through CarPlay (owner's unit)

These make CarPlay calls and audio reach the car over Android Bluetooth. They go with the Android Bluetooth row above. The first two need root and a reboot, and the overlay also needs dm-verity off, so they are tied to this firmware and stay manual: try them only if you are comfortable restoring the unit. The rows marked *Unit setup* are done by Binnacle.

| Change | Why | Command | Undo |
|---|---|---|---|
| Bluetooth overlay: calls, audio and contacts to the car | Android Bluetooth on this firmware offers no hands-free (HFP AG), audio (A2DP source) or phonebook (PBAP) to the car. A runtime resource overlay on `com.android.bluetooth` (package `app.binnacle.overlay.bluetooth`) sets `system_profile_supported_a2dp`, `system_profile_supported_hs_hfp`, `system_profile_supported_pbap` and `system_profile_supported_pbapclient` to true. A normal `adb install` refuses it, so it has to be a static overlay in `/product`. ## What we tried and didn't keep

- **Patching the stock dash** to show the right range: the patched launcher crash-looped the Home screen, so it was reverted. Binnacle replaced it instead.
- **Updating ZLink:** the unit's package manager rolls ZLink back to the preinstalled copy at every boot (`/product/preinstall`), so a sideloaded update doesn't stick.
